AGDB Cloud REST API

Tenantenként perzisztens adat és tényleges használati metrikák.

Minden hitelesített kérés Bearer API kulccsal fut. A rekordok a tenant szerveroldali adatbázisában élnek, az analitika és az audit pedig a szerver által rögzített eseményekből készül.

A példák relatív útvonalakat használnak. A konzol ugyanazon originről hívja a /v1 API-t.

Hitelesítés

A nyilvános regisztráció, bejelentkezés és health végpontokon kívül minden művelethez a Authorization fejléc szükséges.

GET/v1/healthSzolgáltatás állapot
curl --request GET /v1/health
  • 200status és version mezőket tartalmazó válasz.
POST/v1/auth/registerTenant és elsődleges API kulcs létrehozása

Kérés

curl --request POST /v1/auth/register \
  --header "Content-Type: application/json" \
  --data-binary @registration-request.json
MezőTípusJelentés
emailstringA tenant egyedi e-mail azonosítója.

Válaszmezők

MezőTípusJelentés
tenant_idstringA létrehozott tenant azonosítója.
api_keystringAz egyszer megjelenő elsődleges kulcs.
created_atintegerUnix idő másodpercben.
  • 201A tenant létrejött.
  • 400Érvénytelen e-mail vagy kérés.
  • 409Az e-mailhez már tartozik tenant.
POST/v1/auth/loginAPI kulcs ellenőrzése
curl --request POST /v1/auth/login \
  --header "Content-Type: application/json" \
  --data-binary @login-request.json
MezőTípusJelentés
api_keystringA regisztrációkor vagy kulcskorforgatáskor kiadott elsődleges kulcs.

A válasz a tenant azonosítóját, e-mail címét, állapotát és létrehozási idejét tartalmazza.

Bearer fejléc

FejlécÉrték
AuthorizationBearer szóközzel követve a tenant aktív elsődleges API kulcsa.

Tenant és fiók

A tenant metaadatok és a fiók törlése kizárólag a saját API kulccsal érhető el.

GET/v1/tenantauth

A válasz tenant_id, email, status és created_at mezőket ad vissza.

DELETE/v1/accountauth

Visszavonja a tenantot, leállítja a sandboxot, törli a tenant adatkönyvtárát és a tenant mérési tárolóját.

API kulcsok

Egy tenant egy aktív elsődleges kulcsot használ. A teljes kulcs csak regisztrációkor vagy új kulcs kiadásakor érhető el.

GET/v1/apikeysauth

A válasz csak metaadatokat ad: id, name és status. Titkos kulcsot nem ad vissza.

POST/v1/apikeysauthÚj elsődleges kulcs kiadása

A korábbi elsődleges kulcs érvénytelen lesz. A válasz id, key, created_at és status mezőket tartalmaz.

POST/v1/apikeys/primary/rotateauth

Azonos művelet a konkrét elsődleges kulcs útvonalán.

DELETE/v1/apikeys/primaryauth

Visszavonja az elsődleges kulcsot. Ezután új kulcs nélkül a tenant API-ja nem hitelesíthető.

Sandbox

A sandbox a tenant izolált adatbázis-futtatási környezete. A lekérdezési végpontok szükség esetén elindítják, a vezérlő végpontok pedig tényleges állapotot adnak vissza.

GET /v1/sandbox

status értéke running vagy stopped. Futó sandboxnál a válasz started_at_ms mezőt is tartalmaz.

POST /v1/sandbox/start

Elindítja a leállított tenant sandboxot. A changed jelzi, hogy történt-e állapotváltozás.

POST /v1/sandbox/stop

Leállítja a futó sandboxot. A perzisztens tenant adat nem vész el.

POST /v1/sandbox/restart

Leállítja, majd újraindítja a sandboxot.

Adatbázisok

Tenantenként a documents adatbázis érhető el. Rekordok és keresési indexek a tenant szerveroldali adattárában tárolódnak.

GET/v1/databasesauth

A válasz databases tömbjében a használható adatbázisok nevei szerepelnek.

Rekordok

A rekord objektum szöveges keresési törzse a body mező. A content vagy text mező is használható bemenetként. A címkék a tags sztringtömbben adhatók meg.

GET/v1/databases/documents/records?limit={n}&offset={n}auth
ParaméterKorlátJelentés
limit1–1000Visszaadott rekordok száma.
offset0–1000000Lapozási eltolás.

A válasz rows, count, total és took_ms mezőket tartalmaz.

POST/v1/databases/documents/recordsauth

Kérés törzs

MezőTípusJelentés
recordobjectA mentendő rekord.
record.bodystringIndexelhető szöveges tartalom.
record.tagsstring[]Opcionális címkék.
record.embeddingnumber[]Opcionális vektor; hiányában a rendszer beágyazást készít, ha engedélyezett.

A sikeres válasz a szerver által kiosztott id mezőt adja vissza.

GET/v1/databases/documents/records/{id}auth

A teljes perzisztens rekordot adja vissza. Hiányzó azonosítónál 404.

DELETE/v1/databases/documents/records/{id}auth

Törli a rekordot és frissíti a keresési indexet. Hiányzó azonosítónál 404.

Lekérdezés és keresés

A query és search végpont azonos, szerveroldali szöveges keresést futtat. Üres query értéknél tényleges rekordlista készül a megadott limit és offset szerint.

POST/v1/databases/documents/queryauth
MezőTípusJelentés
querystringKeresési szöveg; üresen rekordlista.
limitinteger1–1000 közötti visszaadási limit.
offsetintegerÜres keresésnél lapozási eltolás.

A válaszban rows a rekordokat, hits pedig a keresési azonosítót és relevanciaértéket tartalmazza. A took_ms a szerver által mért végrehajtási idő.

POST/v1/databases/documents/searchauth

A query végponttal azonos kérés- és válaszséma.

Statisztika

A statisztikák a futó tenant adatbázisból és a szerveroldalon perzisztált metrikatárolóból készülnek.

GET/v1/databases/documents/statsauth

database, records és storage_bytes mezőket ad vissza.

GET/v1/statsauth

A felső szinten adatbázis-statisztikát, az analytics mezőben pedig a tenant tényleges API-méréseit adja vissza.

Analitika

A hitelesített API-kérések szerveroldalon kerülnek számlálásra. A metrikák a tenant registry tárolójában maradnak meg, nem a böngésző tárolójában.

GET/v1/analyticsauth
MezőJelentés
total_requestsÖsszes rögzített hitelesített API-kérés.
total_errorsLegalább 400-as státuszú rögzített válaszok száma.
error_rateHibaarány 0 és 1 közötti arányként.
error_rate_percentUgyanez százalékos formában.
avg_latency_msValós szerveroldali átlagos válaszidő.
p95_latency_ms, p99_latency_msHisztogramból számított válaszidő-percentilisek.
hourlyAz utolsó 24 órához tartozó óránkénti számlálók.
endpointsÚtvonal és HTTP metódus szerinti aggregátumok.

Audit

Az audit végpont a szerver által megőrzött legutóbbi hitelesített kéréseket adja vissza időbélyeggel, útvonallal, HTTP státusszal és tényleges válaszidővel.

GET/v1/auditauth

A válasz events tömbjének elemei: timestamp_ms, method, path, status és latency_ms.

Hibaválaszok

Minden hiba JSON objektumot ad error sztringmezővel.

StátuszJelentés
400Hibás JSON, érvénytelen azonosító vagy lapozási paraméter.
401Hiányzó vagy érvénytelen Bearer API kulcs.
404Nem létező útvonal, adatbázis, kulcs vagy rekord.
405Nem támogatott HTTP metódus.
409Már regisztrált e-mail cím.
413Túl nagy kérés törzs.
503A sandbox vagy az adatbázis-művelet nem elérhető.
504A sandbox művelet időtúllépett.
